# dsh-plugin-insights · 产品愿景（Vision）

> 状态：v0.1 草案 · 2026-09-05 · 证据锚点见 [RESEARCH.md](./RESEARCH.md)（全部数字均实测标注 [V]）

## 一句话愿景

**让 DSH 插件生态里的每一个"装不装"的决策都有据可依——成为 DeepSeek Harness 插件生态的质量数据底座（quality data layer）。**

DSH 的哲学是 "Everything is a Plugin"；我们的回答是：**Every plugin deserves an honest number.**

## 我们解决的问题

生态爆发速度超过任何人的策展能力（全部实测 [V]，2026-09-05）：

- DeepSeek Harness ★212k、`@deepseek-ai/dsh` 月下载 127 万；官方 2026-08-13 发布后，`dsh-plugin` topic **3 周冲到 13,592 仓库**。
- 权威策展目录（awesome-dsh-plugin org）收录 **3,159 条**、目录成立不足 4 周、仍在 **~58 条/天** 净增。
- 目录里**中位 star = 3**、12% 零 star、仅 47% 发布到 npm、头部被大仓库 monorepo 子路径污染（46k★ 的无关仓库子目录也算"插件"）。
- 重复严重（file/workspace 类 ≥45 条）、低质泛滥（皮肤/整活/占位）、cordis patch 相互覆盖不兼容。
- 官方姿态：developer preview、README 只给 `dsh-plugin` topic + Discord，**无市场、无目录、无质量门槛**。

结论：**"找得到"已经有人解决（awesome 策展注册表 + dsh-market 应用内一键安装）；"信得过"没人解决。** 用户的真实成本不是发现，而是**在 3000+ 候选里筛掉烂的、重复的、不兼容的**。

## 我们是什么 / 不是什么

**是**（定位陈述）：

> 一个全量、客观、可复现、持续刷新的 **dsh 插件质量评估数据层**：对全量候选做真伪判定 → 对权威集算健康分（可解释、带证据）→ 生态分析（趋势/兼容/缺口）→ 以开放数据快照 + 站点 + agent 可读接口发布，并作为评分标准被已有目录/市场/工具消费。

**不是**（边界，决策过滤器）：

- ❌ 不是第 N 个插件目录/市场/精选列表（不抢 awesome-dsh-plugin / dsh-market 的入口位）。
- ❌ 不做安装执行、托管、交易、抽成（GPT Store 教训：无分发权的商店=垃圾场）。
- ❌ 不做社区评分/投票（可刷、公信力自杀；Openbase 前车之鉴）。
- ❌ 不承诺"安全审计"——健康分是**启发式首筛**，文档与站点必须诚实标注边界（参照 dsh-plugin-health 口径）。
- ❌ 不做需要登录的后端产品。

## 产品支柱

1. **P1 全量覆盖与真伪判定**：抓全 13.6k topic（分片，规避 1000/查询封顶）+ npm + 策展列表三方交叉 → 权威集（通过 manifest 门禁）与噪音分桶（invalid.jsonl）。
2. **P2 客观健康分**：manifest / npm 一致性 / 仓库卫生 / 文档与 i18n / 只读面启发式 / 兼容声明，A–D + 0–100，每项带证据，缺数据明说。
3. **P3 生态分析**：月度新增、发布率、npm 滞后 Top、缺口矩阵（vs 官方内置）、拥挤赛道、兼容矩阵（插件↔dsh 版本、互斥/冲突）。
4. **P4 开放数据与分发**：CC0/MIT 开放快照、稳定 JSON URL、查询接口（by owner/repo）、SVG 健康徽章、站点；**对 AI/agent 爬虫开放**（2026 起 agent 是主要提问入口）。
5. **P5 采纳与标准**：让分数成为 awesome 目录的贡献门槛/卡片字段、dsh-market 的 feed——**被吸收而非竞争**是产品终局形态。

## 指导原则（每个决策过一遍）

1. **纯客观信号优先**：manifest/npm 一致性/发布滞后/仓库卫生先于主观评价；主观项（"这个插件有用吗"）一律后置或不做。
2. **宁缺毋假**：拿不到的数据明说缺失并降级，不假装精确（Skillselion 模式）。
3. **方法论全透明 + 校准集回归**：规则可复现；已知真/假插件编入 seeds，每轮跑批回归。
4. **诚实边界**：明确"启发式、非安全审计"；写面/消毒深检只作为增量信号。
5. **先数据后 UI**：机器可读的 JSON 快照 > 网站；站点只是数据的一个视图。
6. **不做第十一家店**：新能力先问"能不能挂进现有契约（plugins.json 同构）"，而不是开新入口。
7. **成本可续**：零依赖、断点续跑、每周快照节奏、API 预算内运行（token 分片、缓存）。

## 成功指标

**北极星**：健康分/数据被生态采纳的程度——"权威目录（awesome-dsh-plugin）或应用内市场（dsh-market）的卡片/收录流程中出现了我们的分数或数据"（含官方文档引用、desktop 壳内置）。

次级指标（定义见 PRODUCT-PLAN.md）：

- 覆盖：权威集数量、对 topic 全量（13,592）的覆盖率、噪音分桶比例。
- 新鲜度：快照滞后天数（目标 ≤7 天）。
- 公信力：校准集回归通过率 = 100%；评分争议工单响应。
- 传播：健康徽章部署仓库数、score 查询次数、站点访问、GitHub ★/PR/issue 参与。

## 止损 / Kill criteria

- 若 1–2 个季度内 **awesome-dsh-plugin org 或官方下场自己做评分**且口径覆盖我们 → 停止独立评估，将数据/方法论 **贡献 upstream / 被收编**（那也是一种胜利，提前想好 exit 通道）。
- 若生态增速断崖（月净增 <5 条且季度无反弹）→ 降级为归档项目，冻结快照。
- 若评分被广泛质疑游戏化且无法用客观信号修复 → 收缩到纯事实层（真伪判定 + 可安装性），放弃打分。
