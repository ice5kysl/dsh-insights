# dsh-insights · 产品愿景（Vision）

> 状态：**v0.2 · 2026-09-06** · 取代 v0.1 草案 · 对外品牌与域名：**dsh-insights.com** · 引擎仓库：[dsh-insights](https://github.com/ice5kysl/dsh-insights)
> 文档地图：VISION（为什么）→ [PRODUCT-PLAN](./PRODUCT-PLAN.md)（做什么/怎么做）→ [PRODUCT-DESIGN](./PRODUCT-DESIGN.md)（页面与指标）→ [ROADMAP](./ROADMAP.md)（什么时候）· [RESEARCH](./RESEARCH.md)（证据，数字均实测标注 [V]）· [SCHEMA](./SCHEMA.md)（数据契约）· [OUTREACH](./OUTREACH.md)（外发）

## 一句话愿景

**成为 DeepSeek Harness 的"生态与动态全景观察站"：把 dsh 的插件、官方演进与社区信号，变成开放、可验证、持续更新的洞察——帮作者改进、帮用户选择、帮 dsh 官方看见生态全貌。**

DSH 的哲学是 "Everything is a Plugin"；我们的回答是：**Every plugin deserves an honest number —— 而且我们看见的不只是插件。**

## v0.2 相对 v0.1 的关键变化（本次再规划）

1. **品牌与域名落定**：对外 = **dsh-insights**（域名 `dsh-insights.com` 已购入）；引擎代码仓库保持 `dsh-insights`（品牌与引擎分离）。
2. **范围从"插件洞察"升级为"全 dsh 洞察"**：新增 **L2 官方动态**（releases/rc、docs、内置能力演进）与 **L3 生态/社区动态**，不只是 L1 插件质量。
3. **对外产出前置为一等公民**：「致作者的信」（每插件）+「生态周报」（周更）成为常规交付，面向**社区与 dsh 官方**分发。
4. **兼容雷达**（官方 rc 升级 → 预警受影响插件）被明确为高价值独立能力，与插件质量分开演进。

## 我们解决的问题（维持 v0.1 实测结论）

生态爆发速度超过任何人的策展能力（[V] 2026-09-05）：

- `dsh-plugin` topic 3 周冲到 **13,592** 仓库；策展目录净增 ~58 条/天；中位 star = 3、仅 ~47% 发布 npm、头部被 monorepo 子路径污染。
- 重复/低质/不兼容泛滥；官方 developer preview、**无市场、无目录、无质量门槛**。
- 结论不变：**"找得到"已被解决（awesome + dsh-market）；"信得过"没人解决**——用户真实成本是在海量候选中筛掉烂的/重复的/不兼容的；而**官方演进正在加速制造兼容不确定性**。

## 三层产品结构

| 层 | 内容 | 交付形态 |
|---|---|---|
| **L1 · 插件洞察** | 真伪判定 → 权威集 → 健康分（A–D/0–100，带证据）→ 收录矩阵 → 打分明细/同类分位 | 数据快照 + 站点 + 「致作者的信」+ 健康徽章 |
| **L2 · 官方动态** | 官方 releases/rc 节奏、changelog/docs、内置能力演进、`@deepseek-ai` 版本时间线 | 「官方动态」周报小节 + 时间线页 + **rc 兼容雷达** |
| **L3 · 生态/社区** | 全量趋势：新增/消失/star 跳涨/下载/收录/分类拥挤/质量分布 | 「生态周报」（周更，面向社区与官方）+ 月度《dsh 演进报告》 |

## 我们是什么 / 不是什么

**是**：全量、客观、可复现、持续刷新的 **dsh 质量与动态数据层 + 观测报告**：真伪判定 → 健康分（可解释带证据）→ 官方与生态动态 → 开放数据快照 + 站点 + 报告（周报/信件），并作为**评分标准与观测源**被目录/市场/官方/agent 消费。

**不是**（边界，决策过滤器，维持）：

- ❌ 不是第 N 个插件目录/市场/精选列表（不抢 awesome / dsh-market 入口位）。
- ❌ 不做安装执行、托管、交易、抽成。
- ❌ 不做社区评分/投票（可刷、公信力自杀）。
- ❌ 不承诺"安全审计"（启发式首筛，诚实标注）。
- ❌ 不做需登录的后端产品（触发点出现前保持静态/CI 架构）。
- ❌ 不做论坛舆情/情绪抓取（只做可观测公开信号）。

## 用户与主任务

| 用户 | 主任务 |
|---|---|
| 插件使用者/企业 | 安装/选型前 10 秒知道质量与风险面（含写面、消毒、兼容）|
| 插件作者 | 收"致作者的信"：分数/同类定位/最值得做的 3 件事/可复制收录文案 |
| 目录/市场策展人 | 可引用、口径透明的质量 feed 与"优质未收录"榜 |
| dsh 官方/平台方 | 中立可复核的生态度量 + rc 兼容雷达，愿意被引用/合作校核 |
| AI/agent | 稳定 JSON 数据入口（站点/仓库直读，无登录墙）|

## 产品支柱

1. **P1 全量发现与真伪判定**：分片全量抓取 + npm/策展交叉 → 权威集（manifest 门禁）与噪音分桶。
2. **P2 客观健康分**：A–D + 0–100，manifest/npm 一致性/仓库卫生/文档 i18n/只读面启发式，每项带证据与缺失标注。
3. **P3 官方与兼容雷达**：官方 release/rc 时间线、契约演进；官方升级时预警受影响插件（可 PR 校对）。
4. **P4 报告与分发**：「致作者的信」、生态周报、月度报告；社区（LINUX DO/awesome/Discussions）与 dsh 官方渠道；转载许可。
5. **P5 开放数据与采纳**：开放快照、稳定 JSON、SVG 徽章、agent 可读；成为已有目录/市场/官方引用的**数据源（被吸收而非竞争）**。
6. **P6 成本可续**：零依赖、断点续跑、周快照节奏、CI 预算内运行。

## 指导原则

纯客观信号优先 · 宁缺毋假 · 方法论透明 + 校准集回归 · 诚实边界（启发式≠审计）· 先数据后 UI · 不做第十一家店 · 周报/信件**保持中立语气**（数据说话、可复核）。

## 成功指标

- **北极星**：数据/报告被生态采纳——权威目录、应用内市场或 **dsh 官方**引用我们的分数/观测/兼容预警（或收录流程中出现）。
- 覆盖：权威集数、对 topic 全量的覆盖率、噪音分桶比例。
- 新鲜度：快照滞后 ≤7 天；周报稳定外发（社区 + 官方）。
- 采纳：健康徽章部署仓库数、周报转载/订阅、"致作者的信"覆盖与反馈、rc 雷达命中后被作者 PR 采用。
- 传播：站点访问、repo ★/PR/issue 参与。

## 止损 / Kill criteria

- 官方或 awesome org 下场自做评分且口径覆盖我们 → 贡献 upstream / 被收编（预留 exit）。
- 生态增速断崖（月净增 <5 且季度无反弹）→ 归档冻结。
- 评分被广泛质疑且无法用客观信号修复 → 收缩到纯事实层（真伪 + 可安装性 + 官方动态事实时间线），放弃打分。
