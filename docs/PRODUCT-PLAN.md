# dsh-plugin-insights · 产品规划（Product Plan）

> 状态：v0.1 草案 · 2026-09-05 · 与 [VISION.md](./VISION.md) / [ROADMAP.md](./ROADMAP.md) 配套

## 1. 摘要

把 dsh-plugin-insights 从"跑批管线"产品化为 **DSH 插件生态的质量评估数据层**。不做第十一家店：价值交付点是**分数与数据被生态消费**。用户主流程 = 目录/市场卡片上出现健康分 → 作者贴徽章 → 策展人用分做门槛 → agent 代查时能拿到答案。

## 2. 用户与 JTBD

| Persona | 画像 | 主任务 | 现在的替代方案（痛点） | 我们的交付 |
|---|---|---|---|---|
| **安装者** | dsh 重度用户（含中文社区/linux.do/Discord） | 装之前判断值不值、险不险 | 看 star（失真：中位 3、monorepo 污染）/ 评论区 / 逐个试装 | 卡片分数 + 维度证据 + "缺数据明说" |
| **插件作者** | 你的同类（含 ice5kysl 自己） | 让插件被信任、被收录、被安装 | 投稿后被拒不知为何；README 无从下手改进 | 体检报告 + 可执行修复建议 + 徽章 + 客观上榜门槛 |
| **策展人** | awesome-dsh-plugin org、dsh-market 维护者 | 收录/排序有据可依，别背锅 | 纯人工判断 + star + 作者自述 | 可引用、口径透明的质量 feed + 门槛数据 |
| **平台方** | desktop 壳（dataelement 等 3+ 家）、IDE、未来的官方 | 内置"推荐"功能要有数据底座 | 无现成数据 | 数据底座授权 / 上游收编（M4） |

## 3. 价值主张与差异化

| 竞品/现状 | 他们做什么 | 缺口（我们的位置） |
|---|---|---|
| awesome-dsh-plugin org（★14.5k） | 策展注册表 + 站点 + 评论；3159 条每日 CI | 无任何质量字段；收录无客观门槛 |
| dsh-market（★3.2k，应用内） | 一键安装/更新/诊断；消费 plugins.json | 卡片无质量信号；诊断是装完后的运行时冲突 |
| DshMarketPlace | **可安装性实装核验**（2,426 verdicts）+ 风险标记 | 判"装不装得上"而非"值不值得"；覆盖小、含误报（2★ 冷启动、README 数字脱节） |
| deepseek1024.com / Oh-My-DSH 等 | topic 自动同步卡片墙（13,399 / 2,119） | 纯收录 + 热度，无评估 |
| 各家精选列表（Anil/Dominic/…） | 人工二元"收/不收" | 无分级、无量化、口径不一 |

**差异化声明**：全量（对 13.6k topic 分片覆盖）· 客观（纯信号，A–D+0–100）· 透明（规则+证据+规则版本）· 持续（周快照+CI）· 诚实（缺失标注、非安全审计）· 开放（数据快照+agent 可读）。生态内唯一同时满足这些的玩家。

## 4. 场景故事（验收叙事）

**S1 安装者**：在 dsh-market 看到某 sidebar 插件 → 卡片有 `健康 B（78）`，维度展开：manifest ✅ / npm 版本滞后 ⚠️(落后 2 版) / 文档 ✅ 双语 / 只读面 ✅ → 旁边同功能另一款 `A（95）` → 选 A。*（M2 达成后成立；此前用户在站点查）*

**S2 作者**：跑 `npx --yes github:ice5kysl/dsh-plugin-health ice5kysl/dsh-workspace-kit` → 报告给 3 条"怎么修"（发布 npm、补 exports、加 topic）→ 修完分数升 B+ → README 贴徽章 → 投稿 awesome 时自带 health ≥ B 证据 → 收录。

**S3 策展人**：awesome 目录 PR 模板新增一行 `health: B`（数据来自我们的 feed，可复核）→ 新人插件质量门槛客观化，策展人从"凭感觉拒人"变成"引用数据"。

**S4 agent 代查**：用户让 dsh 里的 agent"找个支持归档恢复的文件插件" → agent 查我们的开放数据（稳定 JSON + llms.txt）→ 返回 Top3 带分数与理由。

## 8. 发布与社区计划

**叙事（launch story）**："DSH 插件 3 周 1.36 万个，目录中位 3★、一半没发 npm、头部全是仓库子路径——**没人知道哪些值得装**。dsh-plugin-insights 给全量插件一个诚实的分数：纯客观信号、规则全公开、每周快照、缺数据就明说。"

**渠道与时序**（M1 首个全量快照时）：
1. 仓库公开（ice5kysl 或独立 org，O2）→ 数据快照 + 站点 URL 就绪。
2. awesome-dsh-plugin org：**先以"数据提供者"姿态 PR 集成提案**（M2），同时提交我们的健康分方法论进其 Discussions 征求意见。
3. 社区发布：GitHub Discussions / discord 插件频道 / linux.do / 中文 dsh 社区——以"第一个全量客观评分数据集"叙事，附交互站点与 query CLI。
4. 作者钩子：把 health CLI 放到 npx + badge 演示（拿 ice5kysl 两个插件先示范）。
5. 后续每月：月度生态报告（M3）成为固定"媒体位"。

**Pitch 要点（给 awesome/dsh-market）**：不抢收录权（数据进你们的地方）· 口径透明可复核 · 门槛帮你挡烂插件、降低背锅 · 全部开源免费 · 规则版本可回滚。

## 9. 商业探索（M4，非目标期内不做）

按 RESEARCH.md 跨生态证据：独立评分站无单点收费理由（npms/Advisor/Openbase 全灭）。现实路径：**数据底座授权**给 desktop 壳/IDE/平台方 + 可能的**上游收编**（Smithery→Arcade、PulseMCP→官方注册局 同款终局）。作者侧增值（徽章/报告 Pro）仅在采纳铺开后评估。

## 10. 执行约束

- 零依赖 Node ≥20；无后端；数据在 git 内（data/state 除外）；GITHUB_TOKEN 来自 `gh auth token`。
- 每周节奏与复现命令见 [ROADMAP.md](./ROADMAP.md) §每周执行节奏。
