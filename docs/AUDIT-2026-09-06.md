# P0 — 必须修复

## P0-1 validate 去重键空间不一致（重复追加的根因）

- [x] **状态**：已修复

**位置**：`pipeline/validate/validate.mjs:37,175,194-199`；`pipeline/collect/npm-map.mjs:73`；`pipeline/collect/discover.mjs:24-29`

**根因链**（四机制叠加，均已实锤）：
1. `done.ids` 按 `c.id` **精确匹配**（大小写敏感）。npm-map 用 package.json `repository.url` 的**原样大小写**造 id（作者常写小写：`yuuz12/dsh-webui-auth`）；discover 的 GitHub topic 爬取用规范大小写（`Yuuz12/dsh-webui-auth`）→ 同一仓库两个 id。
2. 改名/owner 转移：npm `repository.url` 指旧名（`KKKneko/…`），GitHub API 返回新名（`umineko987/…`）→ 又一种变体。
3. `validateOne` 用 repo meta 把 full_name 规范化成 canonical（`validate.mjs:83-103`），两个不同 id 校验出的 full_name 相同。
4. `appendFileSync(PLUGINS, …)`（`:194`）盲写，不查 plugins.jsonl 已有 full_name。三次 append（plugins → invalid → done.ids）非事务，中途被杀还有崩溃窗口重复。

**已实锤的重复样例**：大小写变体 `yuuz12` vs `Yuuz12`（行 2082/2115）；改名 `KKKneko` vs `umineko987`（行 1390/3011，full_name 同为 `umineko987/dsh-search-enhance`）；repo 名大小写 `deepseek-harness-pet` vs `DeepSeek-Harness-Pet`。invalid 侧同根因：`Jesse-njx/dsh-plugin-manager` ×2。

**修复方案**：
1. validate 启动时读 `plugins.jsonl` + `invalid.jsonl`，建 **full_name 小写索引**；append 前（含 valid 与 invalid 两条路径）查重，命中则跳过写入（但仍标记 done）。
2. `done.ids` 键统一**小写归一**（写入与比对都 lowercase）；顺手清理 done.ids 里的大小写变体重复行。
3. 候选层可选加固：discover/npm-map 产出的 id 在写入 candidates 时即 lowercase。

**验收标准**：
- 构造含大小写变体与改名变体的测试候选，跑 validate，`plugins.jsonl` 不新增重复行、`done.ids` 只记一次。
- `jq -r '.full_name' data/plugins.jsonl | sort | uniq -d` 输出为空（在 P0-2 清理之后）。

## P0-5 CI 部署闭环断裂 + 周五双 cron 并发

- [x] **状态**：已修复

**位置**：`.github/workflows/refresh.yml:16-18,60-71`；`.github/workflows/pages.yml:3-5`

**问题**：
1. refresh.yml 用 `GITHUB_TOKEN`（checkout 默认凭据）push —— GitHub **不会**因 bot push 触发新的 workflow run，`pages.yml`（`on: push: branches:[main]`）因此不执行。「CI 每日自动刷新站点」闭环实际断开，目前站点没滞后纯粹因为 commit 几乎全靠人工 push。
2. 周五 `7 3 * * *` 与 `7 3 * * 5` 两条 cron **同时触发两条 run**（friday profile 本身包含 daily 全部步骤），并发写 data/、双倍 GitHub API 预算（author-graph ~200 调用 ×2），且 refresh.yml **没有 `concurrency:` 组**（pages.yml 有），`pull --rebase` 只缩小不消除 push 竞态。

**修复方案**：
1. refresh.yml 加 `concurrency: { group: refresh, cancel-in-progress: false }`。
2. cron 收敛为一条 `7 3 * * *`，在 job 内用 `if: github.event.schedule == '7 3 * * 5' || …` 或日期判断（注意 UTC 周五=北京周五，当天 03:07 UTC 判断星期五即可）选择 daily/friday profile。
3. 部署触发三选一：refresh.yml 末尾直接加 Pages 部署步骤；或 pages.yml 改 `workflow_run`（ref 判 main + 非 bot 可直接触发）；或 push 改用 PAT。推荐 `workflow_run`（改动最小）。

**验收标准**：`act`/dry-run 不可用时，至少做到：合并后观察一次真实的 bot commit → Pages 部署被触发（Actions 页面证据）；周五只产生一条 refresh run。
