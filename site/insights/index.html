异常与应对

dominant-owner (low)

  • 可能原因（假设）：模板化批量生成或单一账号集中上传，以量博取曝光。
  • 影响面：规模数字虚胖，低质同质内容增加用户筛选成本，质量分布被稀释。
  • 应对建议：DSH 官方对单账号大批量提交增加人工审核与去重，在统计口径中提供去重后规模，标识模板插件。

npm-stale (low)

  • 可能原因（假设）：发布流程中断、未接入 CI 自动 npm publish，或版本号策略混乱。
  • 影响面：用户安装到旧版本，无法获得修复与新特性，可能引发兼容问题。
  • 应对建议：插件作者接入自动化发布；DSH 在插件页显示 repo/npm 版本差异告警；用户优先选择版本一致的插件。

breaking-release (high)

  • 可能原因（假设）：官方加速迭代，API/schema 调整未完全向后兼容。
  • 影响面：已发布插件可能在新 DSH 上运行失败，用户升级后面临插件不可用风险。
  • 应对建议：官方发布 breaking 前提供迁移指南与宽限期；插件作者订阅 changelog 并做兼容测试；用户升级前核对插件兼容声明。

Anomalies & Response

dominant-owner (low)

  • Possible cause (hypothesis): Template-based bulk generation or single-account mass upload to gain exposure.
  • Impact: Inflated scale numbers, increased user filtering cost, diluted quality distribution.
  • Recommendation: Official review/dedup for mass submissions, provide deduplicated stats, flag template plugins.

npm-stale (low)

  • Possible cause (hypothesis): Broken publish pipeline, no CI auto npm publish, or versioning policy conflict.
  • Impact: Users install outdated builds, miss fixes and features, risk compatibility issues.
  • Recommendation: Plugin authors adopt automated publishing; DSH display repo/npm version drift warning; users prefer version-consistent plugins.

breaking-release (high)

  • Possible cause (hypothesis): Official rapid iteration with non-backward-compatible API/schema changes.
  • Impact: Existing plugins may fail on new DSH; users face plugin breakage after upgrade.
  • Recommendation: Provide migration guide and grace period before breaking; authors subscribe changelog and run compatibility tests; users check compatibility before upgrading.
