## 7. Anomalies and Responses

### growth-anomaly (severity: mid)
- **Possible cause (hypothesis)**: Some automation tool or template library batch-imported plugins after 2026-10-15, or official review channel backlogged and released centrally.
- **Impact**: New additions inflated, top-new list gamed, real community submissions submerged; backend storage and indexing pressure increased.
- **Response**: Cluster source IP/accounts for the 3,986 plugins added between 2026-10-15 and 10-26, flag batch accounts and freeze farming accounts; official may temporarily raise listing threshold (e.g., require README and unique description).

### owner-cluster (severity: mid) — `uckkk`
- **Possible cause (hypothesis)**: `uckkk` uses scripts to batch generate same-prefix plugins, only changing one parameter or template text to occupy slots or boost account weight.
- **Impact**: 1,286 low-quality plugins with avg 56 drag down ecosystem average and leaderboard credibility; users' search results polluted by these names.
- **Response**: Official should ban or downrank the account, remove batch plugins under score 56 with no downloads or stars, and add a “remove batch accounts” filter in leaderboards.

### owner-cluster (severity: mid) — `CAI-MH`
- **Possible cause (hypothesis)**: Similar to `uckkk`, CAI-MH's 9 plugins may come from the same template copy, with one missing README, indicating no manual review.
- **Impact**: Though small in absolute count, it exposes template-copy vulnerabilities in publishing; if not blocked, more small batch accounts may appear.
- **Response**: Manually review all 9 plugins, delete the one without README; add “identical README fingerprint” detection to prevent template cloning.

### dominant-owner (severity: low) — `uckkk`
- **Possible cause (hypothesis)**: Same cause—batch account dominates scale metrics, but stars and downloads have not grown correspondingly, indicating pure quantity filling.
- **Impact**: Official published metrics like “total plugins” and “growth rate” will be questioned for water; ecosystem health assessment must recalculate after excluding this account.
- **Response**: Add a “exclude top batch accounts” view in analytics backend, and publish real scale/growth after exclusion in weekly reports.

### npm-stale (severity: low)
- **Possible cause (hypothesis)**: Plugin authors did not configure CI auto-publish, or forgot to publish after updating local repo version, leaving old package on npm.
- **Impact**: Taking `dsh-market` as example, npm version 1.73.8 is ahead of repo 1.43.0 (possible squatting/mismatch); users may install a version not maintained by author; 10 plugins affected.
- **Response**: Set up automatic `npm publish` workflow for top-download plugins; market page should display “version drift” warning for repo/npm mismatch and suggest Git installation.

### breaking-release (severity: high) — `dsh-v0.2.2-alpha.2`
- **Possible cause (hypothesis)**: Official introduced non-backward-compatible changes to fix critical defects or refactor internal APIs, choosing fast validation in alpha channel.
- **Impact**: All plugins calling old internal interfaces may crash on latest runtime; if not clearly marked, users may face all plugins failing after upgrade.
- **Response**: Official should provide migration checklist with breaking release; plugin authors should immediately run compatibility tests with alpha and declare supported dsh version range in package.json; users should postpone production upgrade during alpha.

## 8. Next Steps & Recommendations

**Plugin authors**
- Check version drift in `npm-stale` list and configure GitHub Actions auto-publish to npm.
- Prioritize Chinese documentation (zh coverage only 48.3%), especially for Chinese community features.
- Stay away from `uckkk`-style template copying; focus on blank official scenarios like memory-knowledge.
- Test compatibility with `dsh-v0.2.2-alpha.2` and declare supported version in plugin metadata.

**Ecosystem users**
- Don't only look at download counts; prefer grade A/S and actively maintained plugins, like `SenmuuuuW/dsh-whale-report` from quadrant.gems.
- Be cautious with high-download grade C plugins (e.g., `LuniteGlaze/dsh-plugin-catalog`); check recent commit time and description.
- Hold off production upgrades to official breaking versions until plugin authors adapt.
- Pay attention to “version drift” and “maintenance stale” labels in official market, avoid installing outdated packages.

**DSH official**
- Ban or downrank batch accounts like `uckkk`, clean template plugins, and publish water-removed scale reports.
- Provide automatic detection and alerts for npm version drift, and force display of health score on market page.
- Expand current 8 official scenarios from 6 to at least 30 plugins each, giving high-quality authors more distribution slots.
- Publish migration guide before breaking changes, and place prominent upgrade notice on docs homepage.
