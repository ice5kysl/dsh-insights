## 7. 异常与应对
### dominant-owner · severity low
- **可能原因（假设）**：uckkk 使用模板批量生成插件以抢占命名空间或刷量，缺乏人工维护。
- **影响面**：规模统计失真，用户通过列表浏览时被低质插件淹没，真实优质插件发现成本升高。
- **应对建议**：DSH 官方对单账号插件数设置阈值并人工审计模板批量号；作者榜与热门榜剔除该账号后重新计算。

### npm-stale · severity low
- **可能原因（假设）**：作者在 GitHub 上快速迭代但未同步发布 npm，或 npm 账号/CI 流程断链。
- **影响面**：用户通过 npm 安装到旧版本，可能遇到已修复的 bug 或缺失的新功能；npmStaleTop 中 Aegis 仓库 v2.9.6 vs npm 0.1.0 差异极大。
- **应对建议**：插件 author 手动或通过 CI 触发 npm publish；官方在插件详情页展示 npm 版本与仓库版本差异提醒。

### breaking-release · severity high
- **可能原因（假设）**：DSH 核心在 v0.1.5 系列进行 API 调整，alpha/rc 阶段引入不兼容变更，属正常迭代但发布节奏紧凑。
- **影响面**：已发布插件可能在新版 DSH 上崩溃或失效；作者需快速适配，否则用户安装后面临故障。
- **应对建议**：官方提前 2 周发布 breaking change 预告与迁移指南；插件作者立即在测试环境运行 dsh-v0.1.5-rc.2 并修复 manifest/API 调用。
