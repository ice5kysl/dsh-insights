## 异常与应对
### growth-anomaly（severity: mid）
- **可能原因（假设）**：发现/收录链路延迟、上游爬取频率下降、或新插件提交集中在 8 月中旬后自然回落。
- **影响面**：周报增长数字失真，可能掩盖真实供给节奏；若持续下降将影响生态热度与用户预期。
- **应对建议**：核查 09-07 至 09-13 的采集日志与失败队列，同步官方发布“增长口径”说明；临时用 7 日均值替代单周增量。

### dominant-owner（severity: low）
- **可能原因（假设）**：uckkk 为模板批量生成账号，可能为自动化测试或 SEO 占位。
- **影响面**：总规模虚增 11%，作者榜与分类分布被扭曲，用户发现真实好插件的信噪比下降。
- **应对建议**：在作者榜增加去水开关；对单账号插件数超阈值（如 >100）自动标记批量号，并在 metrics 中剔除或单列。

### npm-stale（severity: low）
- **可能原因（假设）**：作者仅推仓库不发布 npm；或 CI 发布失败/未配置 npm publish；或抢注导致 npm latest 版本落后。
- **影响面**：用户从 npm 安装到的版本落后于仓库，可能缺少修复或功能；安装侧体验不一致。
- **应对建议**：在安装页对 repo/npm 版本差异强的插件显示警告（参考 npmStaleTop，如 GanyuanRan/Aegis repo 2.9.6 vs npm 0.1.0）；提供一键同步发布 CI 模板。

### breaking-release（severity: high）
- **可能原因（假设）**：官方为 0.1.5 稳定版做预发布，集中引入 API/接口变更。
- **影响面**：插件作者未及时适配将导致运行时崩溃或功能失效，尤其依赖核心 API 的头部插件。
- **应对建议**：官方发布 breaking 变更清单与迁移指南；插件作者应在 rc.2 上跑集成测试，关注 dsh-v0.1.5-rc.1/alpha.2/alpha.1 影响。
