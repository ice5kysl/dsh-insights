## 异常与应对

### dominant-owner（severity: low）
- **可能原因（假设）**：uckkk 为自动化模板批量注册账号，按模板生成大量低差异化插件以占位或刷存在感。
- **影响面**：全生态 12% 插件均分 61，拉低整体质量分布，用户搜索时噪声增加，作者榜被污染。
- **应对建议**：生态治理对单账号插件数设阈值，或对低分批量号降权；用户依靠 curated lists 而非总数。

### concentration（severity: low）
- **可能原因（假设）**：市场入口插件（dsh-market）及高频工具占据主要分发位，长尾插件缺乏曝光机制。
- **影响面**：Top10 下载占 70%，新作者冷启动困难，生态创新可能被抑制。
- **应对建议**：官方增设“新秀榜/编辑推荐”流量位，作者应利用场景包（scenarios）而非单打独斗。

### npm-stale（severity: low）
- **可能原因（假设）**：作者更新仓库后未同步发布 npm，或 npm 账号被抢注导致无法发布。
- **影响面**：用户通过 npm 安装的是旧版，可能缺少新功能或存在安全修复，造成版本碎片化。
- **应对建议**：插件作者设置 CI 自动发布；官方在安装页提示“仓库版本领先 npm”，并提供一键同步指引。

### breaking-release（severity: high）
- **可能原因（假设）**：核心 API 快速迭代，官方在 0.1.5 系列引入 breaking changes，提前发布多个 alpha/rc 以收集反馈。
- **影响面**：现有插件可能直接挂掉，用户升级后遇到不兼容；适配压力集中在作者侧。
- **应对建议**：官方提供迁移指南与兼容层；作者立即对照 changelog 跑适配测试，并关注 dsh-v0.1.5-rc.2 是否稳定。
