## 7. Anomalies and Responses
### dominant-owner · severity low
- **Possible cause (hypothesis)**: uckkk uses templates to mass-generate plugins for namespace squatting or inflated metrics, lacking maintenance.
- **Impact**: scale metrics distorted, users flooded with low-quality plugins, discovery cost rises.
- **Recommendation**: DSH official sets per-account plugin thresholds and manually audits batch accounts; recompute charts after excluding such accounts.

### npm-stale · severity low
- **Possible cause (hypothesis)**: fast GitHub iteration without npm sync, or broken npm/CI pipeline.
- **Impact**: users install outdated versions; Aegis repo 2.9.6 vs npm 0.1.0 exemplifies severe drift.
- **Recommendation**: authors automate npm publish via CI; official displays repo/npm version mismatch prominently.

### breaking-release · severity high
- **Possible cause (hypothesis)**: DSH core API changes in v0.1.5 series, normal but compressed release cycle.
- **Impact**: published plugins may break on new DSH; authors need rapid adaptation.
- **Recommendation**: official provides 2-week breaking change notice and migration guide; authors test against v0.1.5-rc.2 immediately.

## 8. Next Steps by Role
- **Plugin authors**: run compatibility tests against dsh-v0.1.5 breaking changes; sync npm publish with repo; add Chinese docs; abandon template mass release, focus on niches.
