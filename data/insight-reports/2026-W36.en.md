## 4. Anomalies and Response
### dominant-owner (severity: low)
- **Possible cause (hypothesis)**: template batch-generation script abused; one account mass-uploaded low-quality plugins.
- **Impact**: scale inflated, user filtering cost rises, average quality pulled down.
- **Recommendation**: cap per-account plugins or add review; users filter by score/publish status.

### npm-stale (severity: low)
- **Possible cause (hypothesis)**: publish pipeline not auto-syncing repo latest, or manual publish not followed by npm update.
- **Impact**: installs get outdated builds, security/functional fixes not delivered, version drift risks.
- **Recommendation**: adopt CI auto-publish; official UI flags repo/npm version mismatch.

### breaking-release (severity: high)
- **Possible cause (hypothesis)**: dsh core API in alpha fast iteration, official introduces incompatible changes for architecture.
- **Impact**: plugin authors must adapt to 3 breaking versions or face load/crash on latest dsh.
- **Recommendation**: release migration guide and compat layer; authors pin versions and run CI.
