- **可能原因（假设）**：作者发布后未同步 npm，或 npm 包被他人抢注/错配导致 latest 落后于仓库。
- **影响面**：用户通过 npm 安装到旧版本，可能缺少修复或功能，甚至与当前 DSH 不兼容。
- **应对建议**：官方提供 npm 同步检测工具，对漂移插件在详情页显示“版本落后”警告，并推动作者一键重新发布。

### breaking-release · high · dsh-v0.2.1-alpha.2
- **可能原因（假设）**：官方为修复架构或安全缺陷而主动引入 breaking 变更，属正常迭代但风险高。
- **影响面**：所有依赖旧 API 的插件可能在升级后失效，尤其是未发布 npm 或未持续维护的插件。
- **应对建议**：插件作者立即对照 changelog 检查自己的插件，官方可发布迁移指南并给出一段宽限期；用户需暂缓升级到 alpha.2，等待稳定版。
