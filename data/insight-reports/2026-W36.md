## 4. 异常与应对
### dominant-owner（severity: low）
- **可能原因（假设）**：模板批量生成脚本被滥用，单一账号批量上传低质量插件。
- **影响面**：规模数字虚高，用户筛选成本上升，生态质量均值被拉低。
- **应对建议**：官方可限制单账号插件数或增加审核；用户优先按评分/发布状态筛选。

### npm-stale（severity: low）
- **可能原因（假设）**：发布流水线未自动同步仓库最新版本，或作者手动发布后未更新 npm。
- **影响面**：安装侧获得旧版，功能与安全修复无法触达用户，版本漂移引发兼容问题。
- **应对建议**：插件作者接入 CI 自动发布；官方在面板标注仓库/npm 版本差异。

### breaking-release（severity: high）
- **可能原因（假设）**：dsh 核心 API 处于 alpha 快速迭代期，官方为推进架构调整引入不兼容变更。
- **影响面**：插件作者需适配 3 个 breaking 版本，否则可能无法在最新 dsh 加载或崩溃。
- **应对建议**：官方发布迁移指南与兼容层；插件作者锁定版本并及时跑 CI 验证。
