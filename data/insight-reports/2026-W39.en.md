## Anomalies and Responses

### growth-anomaly (mid)
- **Possible cause (hypothesis)**: Batch import or farming, likely from uckkk and similar accounts.
- **Impact**: Inflated scale hides real active developer growth, misleads official resource allocation.
- **Recommendation**: Cluster-check new plugins for abnormal accounts, recalculate growth after removing template copies.

### owner-cluster (mid)
- **Possible cause (hypothesis)**: uckkk mass-generates plugins from templates without functional differentiation.
- **Impact**: Author rankings and category stats polluted, real authors buried, users find good plugins harder.
- **Recommendation**: Restrict or down-rank uckkk and suspected batch accounts, label them as "template batch".

### dominant-owner (low)
- **Possible cause (hypothesis)**: Single account automated bulk registration, lacking community participation.
- **Impact**: Head appears concentrated but innovation source single, squeezing new authors' exposure.
- **Recommendation**: Exclude batch accounts from author leaderboard or deduplicate by plugin function.

### npm-stale (low)
- **Possible cause (hypothesis)**: Authors not publishing npm promptly or CI/CD pipeline broken.
- **Impact**: Install-side users get old versions, may encounter fixed bugs or miss new features.
- **Recommendation**: Add "npm version behind" warning on plugin details page, notify authors to update.

### breaking-release (high)
- **Possible cause (hypothesis)**: DSH core API changes, releasing rc/alpha for quick validation.
- **Impact**: Existing plugin code may be incompatible, causing plugins to fail on new DSH.
- **Recommendation**: Publish migration guides and compatibility matrix; plugin authors should test latest rc locally immediately.
