## Anomalies and Responses

### owner-cluster (severity: mid)
- **Possible cause (hypothesis)**: Account uckkk batch-created 1286 plugins via template copy or automation to inflate counts or test platform limits.
- **Impact**: Pollutes author leaderboard and scale stats, misleads user filtering and official decisions; avg 56 drags overall quality perception.
- **Suggestions**: Manually sample uckkk plugins, mark as low-trust and limit exposure if template batch confirmed; adjust metrics to exclude batch accounts.

### dominant-owner (severity: low)
- **Possible cause (hypothesis)**: Batch account not governed timely, leading to single account 9% abnormal structure.
- **Impact**: Author concentration metrics distorted, top10Share lowered from 2.8%, multi-plugin author stats diluted, affecting diversity assessment.
- **Suggestions**: Exclude uckkk or label as “batch account” in author stats; add a toggle in official dashboard to remove anomalies.

### npm-stale (severity: low)
- **Possible cause (hypothesis)**: Devs update repo but not npm, or publish process not automated; possible npm squatting preventing version update.
- **Impact**: Users get old builds, missing security fixes and features; 10 affected include high-star dsh-web and dsh-market, broad impact.
- **Suggestions**: Add CI check for repo-npm version consistency; remind high-star plugin authors to publish and publicize stale list.

### breaking-release (severity: high)
- **Possible cause (hypothesis)**: Official concentrated breaking API changes in alpha/rc without enough migration window or compat layer.
- **Impact**: Plugin authors face urgent adaptation; yueyexiayu/dsh-shengcheng score dropped 84 to 64, may cascade; user plugins may break after upgrade.
- **Suggestions**: Announce breaking changes at least 2 weeks ahead with migration guide; plugin authors subscribe to releases and set up compat tests; users delay upgrading to breaking versions until adaption done.
