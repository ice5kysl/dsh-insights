## 7. 异常与应对

### growth-anomaly（severity: mid）
- **可能原因（假设）**：某自动化工具或模板库在 2026-10-15 后批量导入了一批插件，或官方审核通道积压后集中放行。
- **影响面**：新增数字虚高，top-new 榜单被刷，真实社区新提交被淹没；后端存储与索引压力增大。
- **应对建议**：对 2026-10-15 至 10-26 期间新增的 3,986 个插件做来源 IP/账号聚类，标记批量号并冻结刷库账号；官方可临时提高上架门槛（如要求 README 与唯一描述）。

### owner-cluster（severity: mid）— `uckkk`
- **可能原因（假设）**：`uckkk` 使用脚本批量生成同名前缀插件，每一件只改一个参数或模板文本，目的是占坑或提升账号权重。
- **影响面**：1,286 个低质插件平均分仅 56，拉低全生态平均分与作者榜可信度；用户搜索时被这些插件的名称污染。
- **应对建议**：官方封禁或降权该账号，并对 56 分以下、无下载或无 star 的批量插件做下架处理，同时在榜单中增加“去批量号”筛选。

### owner-cluster（severity: mid）— `CAI-MH`
- **可能原因（假设）**：与 `uckkk` 类似，CAI-MH 的 9 个插件可能来自同一模板复制，其中 1 个甚至缺失 README，说明未经过人工审核。
- **影响面**：虽然绝对数量少，但暴露出发布流程中模板复制的漏洞，若不阻断，未来可能出现更多小批量号。
- **应对建议**：对 9 个插件逐一人工复核，删除无 README 项；增加“相同 README 指纹”检测，防止模板克隆。

### dominant-owner（severity: low）— `uckkk`
- **可能原因（假设）**：同一原因，批量号主导了规模指标，但 star 与下载未同步增长，说明是纯数量填充。
- **影响面**：官方在对外发布“插件总数”“增速”等指标时会被质疑水分，生态健康评估需剔除该账号后重算。
- **应对建议**：在 analytics 后台增加“排除 top 批量号”的视图，并在周报中同时公布剔除后的真实规模与增速。

### npm-stale（severity: low）
- **可能原因（假设）**：插件作者未配置 CI 自动发布，或本地仓库版本号更新后忘记发布 npm，导致 npm 上仍是旧包。
- **影响面**：以 `dsh-market` 为例，npm 版本 1.73.8 领先仓库 1.43.0（有抢注/错配可能），用户安装到的可能不是作者当前维护的版本；10 个插件受影响。
- **应对建议**：为 top 下载插件建立自动 `npm publish` 流程；市场页对 repo 与 npm 版本不一致的插件显示“版本漂移”警告，并提示用户使用 Git 安装。

### breaking-release（severity: high）— `dsh-v0.2.2-alpha.2`
- **可能原因（假设）**：官方为修复关键缺陷或重构内部 API 而引入了不向后兼容的变更，并选择在 alpha 通道快速验证。
- **影响面**：所有调用旧内部接口的插件可能在最新运行时上崩溃；若未明确标注，用户升级后可能遇到插件全部失效。
- **应对建议**：官方发布 breaking 版本时应同步提供迁移清单；插件作者立即用 alpha 版本跑兼容测试，并在 package.json 中声明兼容 dsh 版本范围；用户在 alpha 阶段暂缓生产环境升级。

## 8. 下一阶段重点与建议

**DSH 官方**
- 封禁或降权 `uckkk` 等批量号，清理模板插件，发布剔除水分后的规模报告。
- 为 npm 版本漂移提供自动检测与告警，并在市场页强制展示健康分。
- 扩展现有 8 个官方场景的收录数量，从 6 个/场景增加到至少 30 个，给高质量作者更多分发位。
- 发布 breaking 变更前提供 migration guide，并在文档站首页设置醒目升级公告。
