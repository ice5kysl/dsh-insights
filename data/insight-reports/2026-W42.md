## 异常与应对
### owner-cluster (mid)

- **应对建议**：DSH 官方对 owner 维度实施插件数/均分双重熔断，下架或隔离 uckkk 及派生插件；报告中单列去水后的核心指标。
### owner-cluster (mid)
- **可能原因（假设）**：账号 CAI-MH 属于小规模批量复制或模板填充，9 个插件均分 57 且 1 个无 README。
- **影响面**：范围有限，但提示可能存在更多未被单一阈值捕获的小型批量号。
- **应对建议**：将 CAI-MH 加入观察名单；对缺 README 插件强制补全否则降低可发现性。
### dominant-owner (low)
- **可能原因（假设）**：与 uckkk 同一账号长期批量生成未清理，形成单一作者占 8% 的极端主导。
- **影响面**：统计数字虚高，活跃率、增长率失真，误导作者判断生态繁荣度。
- **应对建议**：DSH 官方建立作者信誉分并展示在插件页；用户搜索时过滤批量账号内容。
### npm-stale (low)
- **可能原因（假设）**：发布流程未自动化，仓库更新但未同步 npm；部分 npm 包可能被抢注或错配。
- **影响面**：npm 安装用户无法获得最新修复，尤其 dsh-market、dsh-web 等关键插件版本落后，可能遇到已修复 bug。
- **应对建议**：下载页显式展示 repo vs npm 版本差异；核心插件启用 CI 自动发布，作者核查 npm token。
### breaking-release (high)
- **可能原因（假设）**：官方在 v0.2.1-rc.1 与 alpha.3 中调整 API/接口，引入 breaking 变更。
- **影响面**：本周 5 个发布中 2 个 breaking，插件作者需要快速适配；未及时适配将导致插件运行时错误。
- **应对建议**：官方发布 breaking 变更公告与迁移脚本；插件作者立即运行兼容性测试并关注 exports["./client"] 等高频缺陷。
