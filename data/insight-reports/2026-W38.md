## 异常与应对

### growth-anomaly（severity: mid）
- **可能原因（假设）**：批量导入或刷库导致短时大量新增，并非自然开发行为。
- **影响面**：规模统计失真，总插件数、作者数均被注水，掩盖真实活跃度与质量趋势。
- **应对建议**：官方过滤批量账号并发布去水口径；仪表盘发布阶段新增“剔除异常后新增”指标。

### owner-cluster（severity: mid）
- **可能原因（假设）**：账号 uckkk 通过模板批量生成插件，缺乏实质功能与维护。
- **影响面**：推高插件总数、拉低平均分，用户在搜索和榜单中可能被低质内容淹没。
- **应对建议**：将 uckkk 标记为批量号并降权；触发人工审核，必要时下架其插件。

### dominant-owner（severity: low）
- **可能原因（假设）**：单一账号大规模注册，与 owner-cluster 同源，但侧重占比影响。
- **影响面**：uckkk 占全生态 11%，任何作者榜、活跃榜都会被扭曲，破坏公平性。
- **应对建议**：建立作者占比自动预警，单账号插件数超过阈值（如 100）自动进入审核队列。

### npm-stale（severity: low）
- **可能原因（假设）**：发布流水线未同步仓库，或作者未及时 npm publish。
- **影响面**：用户安装侧拿到旧版，可能缺功能或含已知 bug；版本漂移破坏依赖解析。
- **应对建议**：官方在市场中对仓库版本与 npm 不一致的插件加警告标记；插件作者配置自动发布。

### breaking-release（severity: high）
- **可能原因（假设）**：官方在 alpha 阶段引入 API 变更，dsh-v0.1.6-alpha.2 与 alpha.1 均含 breaking。
- **影响面**：依赖旧接口的插件可能崩溃或行为异常，尤其影响 manifest.no-client-export 类插件。
- **应对建议**：官方发布迁移指南和 changelog；插件作者对照检查 client export；用户在升级前备份配置。
